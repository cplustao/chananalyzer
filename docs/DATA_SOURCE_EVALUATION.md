# 日线备用源评估（2026-11-11）

## 问题

前复权（QFQ）研究序列只用 BaoStock。BaoStock 整天不可用时，每日准备会在半小时后重试，最多 3 次；仍然失败就不通过门禁，当天只能做历史复盘。本文评估能否用其他数据源补上缺的几天。

此前出过一次事故：BaoStock 中断期间，AKShare 的 K 线覆盖了 11/04 以后的数据。`load_daily_bars` 只读最新 K 线所属数据源的那一段，结果 26 条序列被截断。现在 AKShare 已不参与前复权序列。

## AKShare（东方财富）对比

样本：随机抽 36 只沪深股票，加上 600519、601988、000001、600036，共 40 只。比较约一年的前复权收盘价：AKShare 实时拉取，BaoStock 取本地库。

| 指标 | 结果 |
| --- | --- |
| 最新收盘价一致 | 40 / 40 |
| 最近 20 个共同交易日比值恒为 1（偏差 < 0.01%） | 38 / 40；另外两只最大偏差 0.11% |
| 一年内两源比值的最大波动 | 0–1.7%（更早的除权日两家算法不同） |
| AKShare 缺少的日期 | 1–10 天，全部是停牌日 |
| 单只请求耗时 | 约 0.1 秒 |

结论：

1. 最近一次除权之后，两家的前复权价格完全相同。因此只缺最近几天时，AKShare 补的数字和 BaoStock 一致。
2. 更早的历史不能混用：两家对早期分红的复权口径不同，最多差 1.7%。
3. 停牌日的处理不同：BaoStock 保留零成交量的平价 K 线，AKShare 直接省略。这项差异让我们发现了引擎输入的问题，已修复：缠论分析现在跳过零成交量的停牌日。

## 如果以后要做 AKShare 接缝补齐

前提：BaoStock 中断的情况确实经常发生。可以在 `data_reliability_samples` 里统计每日准备因中断失败的天数，再决定要不要做。做法：

- 只补“最后一根已保存 K 线之后”的交易日。
- 同时多拉至少 3 个重叠日。重叠日的收盘价和 BaoStock 必须逐日一致（误差 < 0.01%），否则不补。
- 缺口内有除权日的股票不补。
- 补进来的 K 线必须能被识别为“已校验的续接”。当前 `load_daily_bars` 按最新数据源整段读取，直接写入 AKShare 来源会再次截断序列。所以这一步需要数据库迁移，比如增加一个续接来源字段，并相应修改 `load_daily_bars` 和序列覆盖率统计。
- BaoStock 恢复后，下一次刷新用 BaoStock 覆盖这些行。

在此之前，保持现状：BaoStock 不可用时就不通过门禁（fail-closed）。

## mootdx（通达信协议）

本次没有安装测试。mootdx 提供的是不复权 K 线和除权除息信息，前复权要自己计算，算法也不会和 BaoStock 相同。而 AKShare 在“补最近几天”这个场景下已经能和 BaoStock 完全一致。所以 mootdx 不能带来额外的价值，暂不引入，也就不需要多一个依赖和一种协议。只有当 BaoStock 和东方财富同时不可用的情况反复出现时，才值得重新评估。
